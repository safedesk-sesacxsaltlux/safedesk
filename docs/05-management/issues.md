# 이슈관리

> 출처: Notion 「이슈관리」 (마지막 수정: 2026-11-09)

이슈 관리는 프로젝트 진행 중 발생하는 작업, 오류, 변경 요청, 논의 사항을 기록하고 처리 상태를 관리하는 문서이다.

말로만 공유하면 누락되기 쉽기 때문에, 해야 할 일과 문제 상황을 이슈로 등록하여 팀원들이 함께 확인할 수 있도록 한다.

**→ 되도록 노션보다는 GitHub Issues를 이용해주세요!!**

---

## 이슈 관리 작성 기준

| 항목 | 설명 |
| --- | --- |
| 이슈 ID | 이슈를 구분하기 위한 번호 |
| 유형 | 작업, 버그, 변경 요청, 논의, 문서 중 하나로 구분 |
| 제목 | 이슈 내용을 한눈에 알 수 있도록 작성 |
| 내용 | 발생 상황이나 해야 할 일을 구체적으로 작성 |
| 담당자 | 이슈를 처리할 사람 |
| 우선순위 | 높음, 보통, 낮음 |
| 상태 | 예정, 진행중, 해결, 보류 |
| 등록일 | 이슈를 등록한 날짜 |
| 완료일 | 이슈가 해결된 날짜 |

## 이슈 유형 기준

| 유형 | 설명 | 예시 |
| --- | --- | --- |
| 작업 | 새로 구현해야 하는 기능이나 문서 작업 | 로그인 API 구현 |
| 버그 | 의도한 대로 동작하지 않는 오류 | 로그인 실패 시 메시지가 표시되지 않음 |
| 변경 요청 | 기존 기획이나 기능 변경 | 스터디 신청 취소 기능 추가 |
| 논의 | 팀원 간 결정이 필요한 사항 | 모집글 삭제를 실제 삭제로 할지 상태 변경으로 할지 결정 |
| 문서 | 기획서, API 명세서, ERD 등 문서 작성 또는 수정 | API 명세서 상태 코드 수정 |

## 작성 시 주의사항

- 말로만 공유하지 말고 작업과 오류는 이슈로 남긴다.
- 이슈 제목은 한눈에 이해할 수 있게 작성한다.
- 버그 이슈는 발생 상황과 재현 방법을 함께 작성한다.
- 해결된 이슈는 완료일과 처리 내용을 기록한다.
- 기획 변경이 발생하면 관련 문서도 함께 수정한다.
