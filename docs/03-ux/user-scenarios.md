# 사용자 시나리오

> 출처: Notion 「사용자 시나리오」 (마지막 수정: 2026-11-09)

사용자 시나리오는 사용자가 서비스를 어떤 목적과 흐름으로 사용하는지 문장으로 정리한 문서이다.

본 서비스는 Mock AI 1차 상담 → 상담원 연결 → 실시간 상담 → 폭언 감지 및 마스킹 → 자동 경고 → 상담 자동 종료 → 이용정지까지 하나의 흐름으로 처리하는 웹 상담 플랫폼이다.

사용자는 고객, 상담원, 관리자로 구분하며, 실제 AI API 대신 콜센터 FAQ 기반 Mock 데이터와 규칙 기반 폭언 감지 기능을 사용한다.

사용자 시나리오는 화면 설계, API 설계, 기능 구현 및 테스트 케이스 작성의 기준이 된다.

## 주요 사용자

| 사용자 유형 | 설명 |
| --- | --- |
| 비로그인 사용자 | 회원가입 또는 로그인을 통해 서비스를 이용하려는 사용자 |
| 고객 (CUSTOMER) | Mock AI 상담을 이용하고 필요시 상담원에게 연결을 요청하는 사용자 |
| 상담원 (AGENT) | 상담 대기열에서 고객 상담을 수락하고 실시간 채팅으로 문의를 처리하는 사용자 |
| 관리자 (ADMIN) | 상담 이력, 위반 기록, 제재 고객 및 정책을 관리하는 사용자 |
| 이용정지 고객 | 폭언으로 인한 누적 위반으로 일정 기간 상담 이용이 제한된 고객 |

## 시나리오 1. 고객이 회원가입 후 로그인한다

- **사용자:** 비로그인 사용자
- **목적:** 상담 서비스를 이용하기 위해 회원 계정을 생성하고 로그인한다.
- **선행 조건:** 사용자가 로그인하지 않은 상태이다.
- **주요 흐름:**
  1. 사용자가 회원가입 페이지에 접속한다.
  2. 아이디, 비밀번호, 이름, 이메일을 입력한다.
  3. 회원가입 버튼을 클릭한다.
  4. 회원가입이 완료되면 로그인 페이지로 이동한다.
  5. 아이디와 비밀번호를 입력한다.
  6. 로그인에 성공하면 고객 채팅 화면으로 이동한다.
- **예외 흐름:** 이미 사용 중인 아이디 또는 이메일이면 중복 안내 메시지를 표시한다. 필수 입력값이 누락되면 입력 오류를 안내한다. 로그인 정보가 일치하지 않으면 로그인 실패 메시지를 표시한다.
- **관련 기능:** 회원가입, 로그인
- **요구사항 ID:** REQ-001, REQ-002, NFR-001, NFR-002

## 시나리오 2. 고객이 Mock AI를 통해 일반 문의를 해결한다

- **사용자:** 고객
- **목적:** 상담원 연결 없이 배송, 환불, 교환 등의 일반적인 문의를 해결한다.
- **선행 조건:** 고객이 로그인한 상태이며, 이용정지 상태가 아니다. FAQ Mock 데이터가 등록되어 있다.
- **주요 흐름:**
  1. 고객이 채팅 화면에 접속한다.
  2. 상담 시작 버튼을 클릭한다.
  3. 고객이 "배송은 언제 출발하나요?"라고 입력한다.
  4. 시스템이 등록된 FAQ에서 질문과 일치하는 답변을 검색한다.
  5. Mock AI가 FAQ 기반 답변을 순차적으로 표시한다.
  6. 고객이 답변을 확인한다.
  7. 추가 문의가 없으면 상담을 종료한다.
- **예외 흐름:** FAQ에서 적절한 답변을 찾지 못하면 상담원 연결을 안내한다. 고객이 빈 메시지를 전송하면 입력을 요청한다.
- **관련 기능:** 상담 시작, Mock AI 1차 응대, 상담 종료
- **요구사항 ID:** REQ-004, REQ-005, REQ-013

## 시나리오 3. Mock AI 응답이 실패하여 대체 응답을 제공한다

- **사용자:** 고객
- **목적:** Mock AI 응답에 문제가 발생하더라도 상담을 계속 이용한다.
- **선행 조건:** 고객이 Mock AI 상담을 진행 중이다. Mock AI의 지연 또는 오류 테스트 모드가 설정되어 있다.
- **주요 흐름:**
  1. 고객이 채팅창에 질문을 입력한다.
  2. Mock AI 응답 과정에서 오류가 발생하거나 응답이 지연된다.
  3. 시스템이 응답 실패 또는 10초 타임아웃을 감지한다.
  4. FAQ 키워드 매칭으로 대체 답변을 검색한다.
  5. 매칭된 FAQ가 있으면 대체 답변을 제공한다.
  6. 고객은 기존 상담을 종료하지 않고 계속 이용한다.
- **예외 흐름:** 대체 FAQ도 찾지 못하면 상담원 연결을 안내한다. 상담원 연결 요청 시 기존 상담 내역을 유지한다.
- **관련 기능:** AI 응답 실패 시 상담 유지, FAQ 대체 응답, 상담원 연결
- **요구사항 ID:** REQ-005, REQ-006, REQ-007, NFR-006

## 시나리오 4. 고객이 상담원 연결을 요청한다

- **사용자:** 고객
- **목적:** Mock AI 상담으로 해결되지 않은 문의를 상담원에게 직접 문의한다.
- **선행 조건:** 고객이 로그인한 상태이며 Mock AI 상담을 진행 중이다.
- **주요 흐름:**
  1. 고객이 Mock AI 상담을 진행한다.
  2. 고객이 "상담원 연결" 버튼을 클릭한다.
  3. 시스템이 상담원 연결 요청을 접수한다.
  4. 상담 상태가 AI_CHAT에서 QUEUED로 변경된다.
  5. 고객에게 상담원 연결 대기 안내가 표시된다.
  6. 상담원 대기열에 해당 고객의 상담 요청이 등록된다.
  7. 상담원이 수락할 때까지 고객은 대기한다.
- **예외 흐름:** 이미 상담원 연결을 요청한 상태이면 중복 요청을 처리하지 않는다. 상담원이 대기 중이지 않아도 상담 요청은 대기열에 유지된다.
- **관련 기능:** 상담원 연결 요청, 상담 대기열 등록
- **요구사항 ID:** REQ-007, REQ-009

## 시나리오 5. 상담원이 대기 중인 상담을 수락한다

- **사용자:** 상담원
- **목적:** 상담원 연결을 요청한 고객의 상담을 수락한다.
- **선행 조건:** 상담원 계정이 DB에 등록되어 있으며 로그인한 상태이다. 상담 대기열에 요청이 존재한다.
- **주요 흐름:**
  1. 상담원이 아이디와 비밀번호로 로그인한다.
  2. 상담원 콘솔로 이동한다.
  3. 상담 대기열에서 고객의 상담 요청을 확인한다.
  4. 대기 중인 상담을 선택한다.
  5. 상담 수락 버튼을 클릭한다.
  6. 상담 상태가 QUEUED에서 IN_PROGRESS로 변경된다.
  7. 고객과 상담원 화면에 상담 연결 완료 안내가 표시된다.
  8. 상담원이 고객과 실시간 상담을 시작한다.
- **예외 흐름:** 다른 상담원이 이미 수락한 상담이면 수락을 거부하고 안내 메시지를 표시한다. 대기 중인 상담이 없으면 빈 대기열을 표시한다.
- **관련 기능:** 로그인, 상담 대기열 조회, 상담 수락
- **요구사항 ID:** REQ-002, REQ-009, REQ-010

## 시나리오 6. 상담원과 고객이 실시간 채팅으로 상담한다

- **사용자:** 고객, 상담원
- **목적:** 고객의 문의를 실시간 채팅으로 해결한다.
- **선행 조건:** 상담원이 상담을 수락했으며 상담 상태가 IN_PROGRESS이다.
- **주요 흐름:**
  1. 고객이 상담원에게 문의 메시지를 입력한다.
  2. 시스템이 고객 메시지를 저장하고 상담원에게 전달한다.
  3. 상담원 화면에 고객 메시지가 새로고침 없이 표시된다.
  4. 상담원이 고객의 문의를 확인한다.
  5. 상담원이 답변을 입력하고 전송한다.
  6. 고객 화면에 상담원의 답변이 실시간으로 표시된다.
  7. 고객과 상담원이 메시지를 주고받으며 상담을 진행한다.
  8. 문의가 해결되면 고객 또는 상담원이 상담을 종료한다.
- **예외 흐름:** 네트워크 연결이 끊어지면 재연결을 안내한다. 재접속하면 저장된 대화 내용을 다시 조회할 수 있다. 종료된 상담에 메시지를 전송하면 요청을 거부한다.
- **관련 기능:** 실시간 채팅, 상담 종료, 메시지 저장
- **요구사항 ID:** REQ-011, REQ-013, NFR-004, NFR-008

## 시나리오 7. 고객의 폭언이 감지되어 상담원 화면에 마스킹된다

- **사용자:** 고객, 상담원
- **목적:** 고객의 폭언이 상담원에게 직접 노출되지 않도록 보호한다.
- **선행 조건:** 고객과 상담원이 IN_PROGRESS 상태로 상담 중이다. 폭언 감지 규칙이 등록되어 있다.
- **주요 흐름:**
  1. 고객이 상담 중 욕설이 포함된 메시지를 입력한다.
  2. 시스템이 고객 메시지를 수신한다.
  3. 규칙 기반 폭언 감지 기능이 메시지를 분석한다.
  4. 해당 메시지를 폭언으로 분류한다.
  5. 시스템이 욕설을 마스킹한 문장을 생성한다.
  6. 상담원 화면에는 마스킹된 메시지만 표시된다.
  7. 원문과 마스킹된 메시지, 위반 여부가 DB에 저장된다.
  8. 상담원은 욕설 원문을 확인하지 않고 상담을 이어간다.
- **예외 흐름:** 폭언이 감지되지 않은 정상 메시지는 원문 그대로 표시한다. 일반적인 항의나 불만은 폭언 규칙에 해당하지 않으면 정상 메시지로 처리한다.
- **관련 기능:** 폭언 감지·등급 분류, 상담원 화면 마스킹, 원문 보호
- **요구사항 ID:** REQ-014, REQ-015, NFR-005, NFR-007

## 시나리오 8. 폭언이 감지되어 고객에게 자동 경고가 발송된다

- **사용자:** 고객, 상담원
- **목적:** 고객에게 부적절한 표현 사용을 안내하고 상담이 정상적으로 이어지도록 유도한다.
- **선행 조건:** 고객이 상담원과 IN_PROGRESS 상태로 상담 중이며, 해당 상담에서 첫 번째 폭언이 발생한다.
- **주요 흐름:**
  1. 고객이 폭언이 포함된 메시지를 입력한다.
  2. 시스템이 해당 메시지를 폭언으로 분류한다.
  3. 상담원 화면에는 마스킹된 메시지가 표시된다.
  4. 시스템이 해당 상담의 폭언 발생 횟수를 기록한다.
  5. 고객에게 자동 경고 메시지를 발송한다.
  6. 고객 화면에 "부적절한 표현이 감지되었습니다. 반복 시 상담이 종료될 수 있습니다."라는 안내가 표시된다.
  7. 상담원 화면에도 자동 경고 발송 사실이 표시된다.
  8. 고객이 폭언을 중단하면 상담은 정상적으로 계속 진행된다.
- **예외 흐름:** 동일 메시지가 중복 수신되더라도 경고 횟수를 중복 증가시키지 않는다. 경고 발송 후 고객이 정상적인 메시지를 입력하면 상담을 유지한다.
- **관련 기능:** 폭언 감지, 마스킹, 자동 경고, 위반 횟수 기록
- **요구사항 ID:** REQ-014, REQ-015, REQ-016

## 시나리오 9. 고객이 폭언을 반복하여 상담이 자동 종료된다

- **사용자:** 고객, 상담원
- **목적:** 반복적인 폭언으로부터 상담원을 보호하고 정책에 따라 상담을 자동 종료한다.
- **선행 조건:** 고객이 IN_PROGRESS 상태로 상담 중이며, 해당 상담에서 이미 폭언으로 경고를 받은 상태이다.
- **주요 흐름:**
  1. 고객이 첫 번째 폭언으로 자동 경고를 받는다.
  2. 고객이 상담을 계속 진행한다.
  3. 고객이 다시 폭언이 포함된 메시지를 전송한다.
  4. 시스템이 해당 메시지를 폭언으로 분류한다.
  5. 상담별 폭언 발생 횟수가 자동 종료 기준에 도달한다.
  6. 시스템이 상담을 자동 종료한다.
  7. 상담 상태가 IN_PROGRESS에서 CLOSED로 변경된다.
  8. 고객에게 반복적인 폭언으로 상담이 종료되었다는 안내를 표시한다.
  9. 상담원에게 자동 종료 알림을 표시한다.
  10. 종료된 상담은 더 이상 메시지를 주고받을 수 없다.
- **예외 흐름:** 자동 종료 이후 메시지를 전송하면 요청을 거부한다. 이미 종료된 상담에 대해 중복 종료 처리가 발생하지 않도록 한다.
- **관련 기능:** 자동 경고, 상담 자동 종료, 상담 상태 관리
- **요구사항 ID:** REQ-016, REQ-017, REQ-020

## 시나리오 10. 반복 폭언으로 상담이 종료된 고객에게 이용정지가 적용된다

- **사용자:** 고객
- **목적:** 반복적인 폭언으로 상담이 강제 종료된 고객에게 제재 정책을 적용한다.
- **선행 조건:** 고객의 상담이 폭언으로 CLOSED 처리되었다. 이용정지 정책이 등록되어 있다.
- **주요 흐름:**
  1. 고객의 상담이 폭언으로 자동 종료된다.
  2. 시스템이 해당 상담의 강제 종료 이력을 저장한다.
  3. 고객의 누적 강제 종료 횟수를 확인한다.
  4. 누적 횟수에 해당하는 제재 정책을 조회한다.
  5. 최초 위반 고객에게 7일 이용정지를 적용한다.
  6. 제재 시작 시간과 해제 예정 시간을 저장한다.
  7. 고객에게 이용정지 사유와 기간을 안내한다.
  8. 관리자 화면의 제재 고객 목록에 해당 고객이 표시된다.
- **예외 흐름:** 동일 상담의 강제 종료 이벤트가 중복 처리되어도 제재는 한 번만 적용한다. 과거 위반 이력이 있는 고객은 누적 횟수에 따른 다음 단계의 제재를 적용한다.
- **관련 기능:** 위반 이력 누적, 자동 이용정지, 제재 고객 조회
- **요구사항 ID:** REQ-020, REQ-021, REQ-025

## 시나리오 11. 이용정지된 고객이 다시 상담을 시도한다

- **사용자:** 이용정지 고객
- **목적:** 상담 서비스를 다시 이용하려고 시도한다.
- **선행 조건:** 고객이 로그인한 상태이며, 현재 이용정지 기간이 만료되지 않았다.
- **주요 흐름:**
  1. 고객이 서비스에 로그인한다.
  2. 고객 채팅 화면에 접속한다.
  3. 상담 시작 버튼을 클릭한다.
  4. 시스템이 고객의 이용정지 상태를 확인한다.
  5. 이용정지 중인 고객임을 확인한다.
  6. 상담 시작 요청을 거부한다.
  7. 고객에게 이용정지 사유와 해제 예정 일시를 표시한다.
  8. 고객은 새로운 상담을 시작할 수 없다.
- **예외 흐름:** 제재 기간이 만료된 경우 상담 시작을 허용한다. 관리자가 제재를 수동 해제한 경우에도 상담을 시작할 수 있다.
- **관련 기능:** 정지 고객 상담 차단, 정지 자동 해제
- **요구사항 ID:** REQ-022, REQ-023

## 시나리오 12. 상담원이 고객의 과거 위반 이력을 확인한다

- **사용자:** 상담원
- **목적:** 과거 위반 이력이 있는 고객의 상담을 사전에 파악한다.
- **선행 조건:** 상담원이 로그인한 상태이며, 고객의 상담 요청을 수락하였다.
- **주요 흐름:**
  1. 상담원이 대기열에서 상담 요청을 확인한다.
  2. 상담 수락 버튼을 클릭한다.
  3. 상담원 화면에 고객의 기본 정보가 표시된다.
  4. 시스템이 고객의 과거 위반 이력을 조회한다.
  5. 고객의 누적 위반 횟수와 최근 위반 일자를 표시한다.
  6. 상담원은 해당 정보를 참고하여 상담을 진행한다.
- **예외 흐름:** 고객의 위반 이력이 없으면 위반 이력 없음으로 표시한다. 상담원에게는 폭언 원문을 제공하지 않는다.
- **관련 기능:** 강성 고객 이력 표시, 상담 수락
- **요구사항 ID:** REQ-010, REQ-019
- **우선순위:** Should

## 시나리오 13. 관리자가 제재 고객을 조회하고 수동으로 해제한다

- **사용자:** 관리자
- **목적:** 이용정지 고객의 제재 상태를 확인하고 필요한 경우 수동 해제한다.
- **선행 조건:** 관리자가 ADMIN 계정으로 로그인한 상태이며, 제재 이력이 존재한다.
- **주요 흐름:**
  1. 관리자가 로그인한다.
  2. 관리자 화면에서 제재 고객 관리 메뉴로 이동한다.
  3. 이용정지 중인 고객 목록을 확인한다.
  4. 특정 고객을 선택한다.
  5. 고객의 누적 위반 횟수, 제재 사유, 제재 기간을 확인한다.
  6. 제재 해제가 필요하다고 판단하면 해제 버튼을 클릭한다.
  7. 시스템이 제재 상태를 해제 처리한다.
  8. 해제된 고객은 다시 상담을 이용할 수 있다.
- **예외 흐름:** 이미 해제되거나 만료된 제재는 중복 해제할 수 없다. 관리자 권한이 없는 사용자가 접근하면 요청을 거부한다.
- **관련 기능:** 로그인, 제재 고객 조회·해제
- **요구사항 ID:** REQ-002, REQ-025, NFR-003

## 시나리오 14. 관리자가 폭언 원문과 위반 기록을 조회한다

- **사용자:** 관리자
- **목적:** 폭언으로 분류된 메시지의 원문과 위반 내역을 확인한다.
- **선행 조건:** 관리자가 로그인한 상태이며, 폭언 위반 기록이 존재한다.
- **주요 흐름:**
  1. 관리자가 관리자 화면에 접속한다.
  2. 제재 고객 목록 또는 상담 이력에서 위반 기록을 선택한다.
  3. 고객의 위반 발생 일시와 분류 등급을 확인한다.
  4. 위반 메시지 상세 조회를 선택한다.
  5. 시스템이 관리자 권한을 확인한다.
  6. 관리자에게 고객이 입력한 원문과 마스킹된 문장을 표시한다.
  7. 관리자는 해당 위반 기록을 확인한다.
- **예외 흐름:** 고객 또는 상담원이 원문 조회를 요청하면 접근을 거부한다. 존재하지 않는 위반 기록이면 조회 실패 메시지를 표시한다.
- **관련 기능:** 위반 원문 조회, 상담 이력 조회
- **요구사항 ID:** REQ-026, REQ-030, NFR-005

## 시나리오 15. 상담원과 관리자가 종료된 상담 이력을 확인한다

- **사용자:** 상담원, 관리자
- **목적:** 종료된 상담의 대화 내용과 상담 결과를 확인한다.
- **선행 조건:** 상담이 종료되었으며 상담 메시지와 종료 정보가 DB에 저장되어 있다.
- **주요 흐름:**
  1. 상담원 또는 관리자가 상담 이력 메뉴로 이동한다.
  2. 종료된 상담 목록을 확인한다.
  3. 특정 상담을 선택한다.
  4. 상담 시작·종료 시간, 상담 상태, 종료 사유를 확인한다.
  5. 해당 상담의 메시지 이력을 확인한다.
  6. 시스템이 FAQ 유형과 종료 사유를 기반으로 생성한 Mock 상담 요약을 표시한다.
  7. 사용자는 상담 결과를 확인한다.
- **예외 흐름:** 상담 이력이 없으면 안내 메시지를 표시한다. 상담원은 자신이 담당하지 않은 상담에 접근할 수 없다. Mock 요약 생성에 실패한 경우에도 상담 원본 이력은 조회할 수 있다.
- **관련 기능:** 상담 요약 저장, 상담 이력 조회
- **요구사항 ID:** REQ-029, REQ-030, NFR-004

## 시나리오 16. 관리자가 상담 통계 대시보드를 확인한다

- **사용자:** 관리자
- **목적:** 상담 현황과 폭언 대응 및 제재 처리 결과를 통계로 확인한다.
- **선행 조건:** 관리자가 로그인한 상태이며, 상담 및 위반 기록이 DB에 저장되어 있다.
- **주요 흐름:**
  1. 관리자가 관리자 대시보드로 이동한다.
  2. 조회할 기간을 선택한다.
  3. 시스템이 기간별 상담 데이터를 조회한다.
  4. 전체 상담 건수와 Mock AI 단독 해결 비율을 표시한다.
  5. 폭언 발생 건수와 자동 종료 건수를 표시한다.
  6. 신규 제재 건수와 활성 제재 고객 수를 표시한다.
  7. 관리자는 통계 차트와 수치를 확인한다.
- **예외 흐름:** 조회 기간에 데이터가 없으면 0건으로 표시한다. 잘못된 기간을 입력하면 기간을 다시 선택하도록 안내한다.

## 시나리오 17. 관리자가 제재 정책을 수정한다

- **사용자:** 관리자
- **목적:** 서비스 운영 기준에 따라 자동 종료 횟수와 이용정지 기간을 변경한다.
- **선행 조건:** 관리자가 로그인한 상태이며, 제재 정책 수정 기능이 구현되어 있다.
- **주요 흐름:**
  1. 관리자가 제재 정책 관리 화면에 접속한다.
  2. 현재 적용 중인 자동 종료 기준과 제재 기간을 확인한다.
  3. 자동 종료 경고 횟수 또는 이용정지 기간을 수정한다.
  4. 저장 버튼을 클릭한다.
  5. 시스템이 입력값을 검증한다.
  6. 변경된 정책을 저장한다.
  7. 이후 발생하는 위반에 변경된 정책을 적용한다.
- **예외 흐름:** 음수 또는 허용되지 않은 값을 입력하면 저장을 거부한다. 정책 수정 권한이 없는 사용자의 접근은 차단한다.
- **관련 기능:** 제재 정책 설정
- **요구사항 ID:** REQ-024
- **우선순위:** Should

  6. 이용정지 중이면 해제 예정일을 확인한다.

## 시나리오 19. 악성 상담 종료 후 상담원에게 회복 시간이 적용된다

- **사용자:** 상담원
- **목적:** 폭언 상담 직후 일정 시간 동안 신규 상담을 수락하지 않고 회복 시간을 확보한다.
- **선행 조건:** 상담원이 담당하던 상담이 폭언으로 자동 종료되었으며, 회복 시간 기능이 구현되어 있다.
- **주요 흐름:**
  1. 고객의 반복 폭언으로 상담이 자동 종료된다.
  2. 시스템이 상담원에게 상담 종료 사실을 안내한다.
  3. 상담원 상태를 일시적인 회복 시간 상태로 변경한다.
  4. 회복 시간 동안 신규 상담 수락을 제한한다.
  5. 상담원 화면에 회복 시간 종료 예정 시각을 표시한다.
  6. 회복 시간이 종료되면 다시 상담을 수락할 수 있다.
- **예외 흐름:** 회복 시간이 이미 적용 중이면 중복 적용하지 않는다. 회복 시간이 만료되면 정상 상담 가능 상태로 전환한다.
- **관련 기능:** 상담원 회복 시간
- **요구사항 ID:** REQ-033
- **우선순위:** Should

### 작성 시 주의사항

- 사용자 시나리오는 개발 로직보다 사용자의 목적과 실제 행동 흐름을 중심으로 작성한다.
- Mock AI 상담은 실제 생성형 AI API를 사용하지 않고 FAQ 기반 응답으로 동작한다.
- 정상 흐름뿐 아니라 응답 오류, 상담 연결 실패, 폭언 반복, 이용정지 등의 예외 흐름을 포함한다.
- 폭언 메시지는 상담원에게 전달되기 전에 마스킹되어야 한다.
- 상담원과 관리자는 각각 자신의 권한에 맞는 정보만 조회할 수 있어야 한다.
- 시나리오에서 사용하는 상담 상태와 제재 기준은 정책정의서와 동일하게 유지한다.
- Should 기능은 7일 개발 일정에 따라 제외될 수 있으므로 핵심 시연 흐름과 분리한다.
- 사용자 시나리오가 변경되면 요구사항 정의서, 화면 설계서, API 명세서 및 테스트 케이스에도 변경 사항을 반영한다.

사용자 시나리오는 사용자가 서비스를 어떤 목적과 흐름으로 사용하는지 문장으로 정리한 문서이다.

사용자가 목적을 달성하기 위해 기능들을 어떤 순서로 사용하는지 정리한다.

화면 설계, API 설계, 기능 구현 범위를 정할 때 기준이 된다.
