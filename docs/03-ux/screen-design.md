## 3. 작성 시 주의사항

- 화면 목록에는 주요 화면을 빠짐없이 작성한다.
- URL은 프론트엔드 라우팅 기준으로 작성한다.
- 연결 API는 API 명세서와 동일하게 작성한다.
- 화면별 상세에는 화면 목적, 주요 UI, 사용자 액션을 작성한다.
- 와이어프레임은 최종 디자인이 아니라 화면 구조를 확인하기 위한 초안이다.
- 사용자 흐름도에 등장한 화면은 화면 설계서에도 포함되어야 한다.

## 1. 공통 설계 기준

### 사용자 권한

| 권한 | 이용 범위 |
| --- | --- |
| 고객 `CUSTOMER` | Mock AI 상담, 상담원 연결, 실시간 채팅, 본인 상담 이력 조회 |
| 상담원 `AGENT` | 대기 상담 조회·수락, 실시간 상담, 권한이 있는 상담 이력 조회 |
| 관리자 `ADMIN` | 제재 관리, 폭언 원문 확인, 정책 관리, 상담 이력·통계 조회 |

### 화면 및 상태 처리

- 비로그인 사용자가 인증이 필요한 화면에 접근하면 로그인 화면으로 이동한다.
- 로그인 성공 시 서버에서 확인한 사용자 권한에 맞는 화면으로 이동한다.
- 이용정지 고객도 로그인은 가능하지만 새로운 상담 시작은 제한한다.
- 상담 상태는 `AI_CHAT`, `QUEUED`, `IN_PROGRESS`, `CLOSED`로 구분한다.
- 폭언 감지, 마스킹, 경고 횟수 증가, 자동 종료, 이용정지 여부는 서버에서 판단한다.
- 상담원에게는 폭언 원문을 전달하지 않고 마스킹된 메시지만 표시한다.
- 폭언 원문 조회는 관리자 전용 기능으로 분리한다.
- 회원가입 완료, 경고, 상담 수락 실패, 제재 해제 확인, 연결 끊김 등은 별도 페이지 대신 모달·알림·화면 내 상태로 표시한다.
- 고객의 본인 상담 이력은 추가 기능으로 관리하되, 사용자 흐름도에 포함되어 있으므로 화면 목록에도 작성한다.

### URL 및 API 표기

- URL의 `:consultationId`, `:sanctionId`는 실제 데이터 식별자로 대체한다.
- 아래 REST API 경로는 **설계 제안**이다.
- 실시간 채팅의 `WS` 표기는 WebSocket 연결을 의미한다. 접속 경로, 메시지 형식, 이벤트명은 WebSocket 명세서에서 확정한다.

## 3. 화면별 상세

# 고객 페이지

### SCR-004. 고객 메인 페이지

- **화면 목적:** 고객이 상담을 시작하고 본인의 이용 상태를 확인한다.
- **주요 UI:** 고객 이름, 상담 시작 버튼, 이용 상태 안내, 내 상담 이력 버튼, 로그아웃 버튼.
- **사용자 액션:**
  - 상담 시작 버튼을 눌러 새로운 Mock AI 상담을 생성한다.
  - 정상 상태라면 Mock AI 상담 화면으로 이동한다.
  - 제재 중이면 이용정지 안내 화면으로 이동한다.
  - 내 상담 이력을 조회하거나 로그아웃한다.
- **상태 및 예외:** 상담 생성 실패 시 재시도 안내를 표시한다. 상담 시작 시 서버에서도 제재 상태를 확인한다.

### SCR-005. Mock AI 상담 화면

- **화면 목적:** FAQ 기반 Mock AI 응대로 고객 문의를 처리하고, 미해결 문의를 상담원에게 연결한다.
- **주요 UI:** AI 상담 안내, 대화 내역, 문의 입력란, 전송 버튼, 답변 출력 상태, 상담원 연결 버튼, 상담 종료 버튼.
- **사용자 액션:**
  - 문의를 입력하고 전송한다.
  - 순차 표시되는 Mock AI 답변을 확인한다.
  - 문의가 해결되면 상담을 종료하고 종료 결과 화면으로 이동한다.
  - 미해결 시 상담원 연결을 요청하고 대기 화면으로 이동한다.
- **상태 및 예외:** 응답 실패·시간 초과 시 대체 안내와 상담원 연결 버튼을 표시한다. 연결 요청 실패 시 현재 화면에서 재시도할 수 있다.
- **처리 기준:** 실제 LLM 호출 없이 사전 정의된 FAQ 응답을 사용한다.

### SCR-006. 상담원 연결 대기 화면

- **화면 목적:** 상담원 연결 요청이 접수되었음을 알리고 연결 진행 상태를 표시한다.
- **주요 UI:** 연결 대기 안내, 대기 중 표시, 연결 상태 문구, 상담 정보.
- **사용자 액션:**
  - 연결 대기 상태를 확인한다.
  - 상담원이 수락하면 실시간 채팅 화면으로 자동 이동한다.
- **상태 및 예외:**
  - `QUEUED` 상태에서는 대기 안내를 유지한다.
  - `IN_PROGRESS` 상태가 되면 고객 실시간 채팅 화면으로 이동한다.
  - 새로고침·재접속 시 서버의 상담 상태를 다시 조회한다.
  - 연결 오류 시 재연결 상태와 재시도 안내를 표시한다.
- **표시 기준:** 대기 순번이나 예상 대기 시간은 서버에서 제공할 때만 표시한다.

### SCR-007. 고객 실시간 채팅 화면

- **화면 목적:** 고객이 상담원과 실시간으로 대화하고 경고 및 상담 상태를 확인한다.
- **주요 UI:** 상담원 연결 정보, 대화 내역, 메시지 입력란, 전송 버튼, 경고 알림, 연결 상태 배너.
- **사용자 액션:**
  - 메시지를 입력하고 전송한다.
  - 상담원 답변과 경고 알림을 확인한다.
  - 연결이 끊기면 재연결 진행 상태를 확인하거나 재시도한다.
  - 상담 종료 시 종료 결과 화면으로 이동한다.
- **상태 및 예외:**
  - `IN_PROGRESS` 상태에서만 메시지를 전송할 수 있다.
  - 폭언 경고 발생 시 서버에서 받은 경고 횟수와 안내 문구를 표시한다.
  - 자동 종료 시 입력을 비활성화하고 종료 사유를 안내한다.
  - 재연결 후 상담 상태와 메시지 이력을 다시 조회한다.
  - 이미 종료된 상담이면 종료 결과 화면으로 이동한다.

### SCR-008. 상담 종료 결과 화면

- **화면 목적:** 고객과 상담원이 상담 종료 여부와 사유를 확인한다.
- **주요 UI:** 상담 번호, 종료 상태, 종료 시각, 종료 사유, 권한별 이동 버튼.
- **사용자 액션:**
  - 고객은 고객 메인 또는 내 상담 이력으로 이동한다.
  - 제재가 적용된 고객은 이용정지 안내를 확인한다.
  - 상담원은 상담원 콘솔 또는 상담 이력으로 이동한다.
- **상태 및 예외:**
  - `CLOSED`는 정상 종료로 표시한다.
  - `CLOSED`는 정책 위반에 따른 자동 종료로 표시한다.
  - Mock AI 상담만 이용하고 종료한 경우도 이 화면을 사용한다.
  - 종료된 상담에서는 메시지를 추가로 전송할 수 없다.

### SCR-009. 이용정지 안내 화면

- **화면 목적:** 고객에게 상담 이용 제한 사유와 적용 기간을 안내한다.
- **주요 UI:** 이용정지 안내 문구, 제재 사유, 시작·종료 일시, 고객 메인 이동 버튼, 상태 다시 확인 버튼.
- **사용자 액션:**
  - 제재 사유와 기간을 확인한다.
  - 이용 상태를 다시 조회한다.
  - 제재가 만료되거나 해제되면 고객 메인에서 상담을 다시 시작한다.
- **상태 및 예외:** 유효한 제재가 있으면 신규 상담 시작을 차단한다. 해제·만료 여부는 서버 응답을 기준으로 표시한다.

### SCR-019. 내 상담 이력

- **화면 목적:** 고객이 본인의 이전 상담과 종료 결과를 확인한다.
- **주요 UI:** 본인 상담 목록, 상담 일시, 종료 상태, 상세 보기 버튼, 목록 페이지 이동, 고객 메인 이동 버튼.
- **사용자 액션:**
  - 본인 상담 목록을 확인한다.
  - 상담을 선택하여 상담 상세 화면으로 이동한다.
  - 고객 메인으로 돌아간다.
- **상태 및 예외:** 상담 이력이 없으면 안내 문구를 표시한다. 다른 고객의 상담은 조회할 수 없도록 서버에서 제한한다.
- **구현 범위:** 추가 기능으로 관리한다.

# 상담사 페이지

### SCR-010. 상담원 콘솔

- **화면 목적:** 상담원이 대기 중인 상담을 확인하고 수락한다.
- **주요 UI:** 대기 상담 목록, 상담 요청 시각, 상담 선택 영역, 수락 버튼, 목록 새로고침 버튼, 상담 이력 메뉴.
- **사용자 액션:**
  - 대기 상담 목록을 확인한다.
  - 상담을 선택하고 수락 버튼을 누른다.
  - 수락 성공 시 해당 상담의 실시간 채팅 화면으로 이동한다.
  - 상담 이력 메뉴로 이동한다.
- **상태 및 예외:**
  - 대기 상담이 없으면 빈 상태 안내를 표시한다.
  - 다른 상담원이 먼저 수락한 경우 수락 불가 안내 후 목록을 갱신한다.
  - 수락 요청 처리 중에는 중복 클릭을 방지한다.
- **화면 구성:** 사용자 흐름도의 ‘상담 대기 목록’과 ‘상담 수락’은 이 화면에 포함한다.

### SCR-011. 상담원 실시간 채팅 화면

- **화면 목적:** 상담원이 기존 문의 내용을 확인하고 폭언 노출을 줄이면서 고객을 응대한다.
- **주요 UI:** 상담 정보, 이전 Mock AI 대화 내역, 실시간 대화 영역, 답변 입력란, 전송 버튼, 경고 상태, 상담 종료 버튼, 연결 상태 배너.
- **사용자 액션:**
  - 이전 Mock AI 상담 내역을 확인한다.
  - 고객 메시지에 답변한다.
  - 상담 종료 버튼을 누르고 확인 후 정상 종료한다.
  - 자동 종료 알림을 확인하고 종료 결과 화면으로 이동한다.
- **상태 및 예외:**
  - 폭언 메시지는 서버에서 마스킹된 형태로만 수신·표시한다.
  - 폭언 원문 보기 기능은 제공하지 않는다.
  - 상담 종료 후 입력과 전송을 비활성화한다.
  - 재연결 시 상담 상태와 메시지 내역을 복원한다.

### SCR-008. 상담 종료 결과 화면

- **화면 목적:** 고객과 상담원이 상담 종료 여부와 사유를 확인한다.
- **주요 UI:** 상담 번호, 종료 상태, 종료 시각, 종료 사유, 권한별 이동 버튼.
- **사용자 액션:**
  - 고객은 고객 메인 또는 내 상담 이력으로 이동한다.
  - 제재가 적용된 고객은 이용정지 안내를 확인한다.
  - 상담원은 상담원 콘솔 또는 상담 이력으로 이동한다.
- **상태 및 예외:**
  - `CLOSED`는 정상 종료로 표시한다.
  - `CLOSED`는 정책 위반에 따른 자동 종료로 표시한다.
  - Mock AI 상담만 이용하고 종료한 경우도 이 화면을 사용한다.
  - 종료된 상담에서는 메시지를 추가로 전송할 수 없다.

### SCR-016. 상담 이력 목록

- **화면 목적:** 상담원과 관리자가 조회 권한에 해당하는 종료 상담을 찾는다.
- **주요 UI:** 기간 검색, 종료 상태 필터, 상담 목록, 상담 번호·상담 시각·종료 상태, 상세 보기, 목록 페이지 이동.
- **사용자 액션:**
  - 기간과 상태로 상담을 조회한다.
  - 상담을 선택하여 상담 상세 화면으로 이동한다.
- **상태 및 예외:** 조회 결과가 없으면 빈 상태를 표시한다. 상담원에게 제공할 상담 범위는 권한 정책에 따라 서버에서 제한한다.
- **표시 기준:** 이력 화면의 일반 메시지 데이터에는 폭언 원문을 포함하지 않는다.

### SCR-017. 상담 상세 화면

- **화면 목적:** 권한이 있는 사용자가 상담 내용과 요약, 종료 결과를 확인한다.
- **주요 UI:** 상담 기본 정보, 메시지 내역, Mock 상담 요약, 상담 상태, 종료 시각·사유, 목록으로 돌아가기 버튼.
- **사용자 액션:**
  - 상담 메시지와 요약을 확인한다.
  - 종료 상태와 사유를 확인한다.
  - 진입한 권한별 상담 이력 목록으로 돌아간다.
- **상태 및 예외:**
  - 고객은 본인 상담만 조회한다.
  - 상담원은 권한 정책에 허용된 상담만 조회한다.
  - 서버에서 상담별 조회 권한을 확인한다.
  - 요약 생성 전·생성 실패·요약 없음 상태를 구분한다.
  - 종료된 상담은 읽기 전용으로 표시한다.
- **원문 처리:** 폭언 원문은 이 화면에 표시하지 않는다. 관리자는 별도의 제재 상세 화면에서 원문을 확인한다.

# 관리자 페이지

### SCR-012. 관리자 대시보드

- **화면 목적:** 관리자가 서비스 운영 현황을 확인하고 관리 기능으로 진입한다.
- **주요 UI:** 운영 현황 요약 카드, 제재 관리·정책 관리·상담 이력·통계 메뉴, 로그아웃 버튼.
- **사용자 액션:**
  - 주요 운영 수치를 확인한다.
  - 제재 관리, 정책 관리, 상담 이력, 통계 화면으로 이동한다.
- **상태 및 예외:** 데이터가 없으면 0건 또는 데이터 없음으로 표시한다. 조회 실패 시 재시도 안내를 제공한다.
- **화면 구분:** 이 화면은 운영 현황 요약과 메뉴 진입을 담당하고, 상세 통계는 통계 대시보드에서 제공한다.

### SCR-013. 제재 관리 화면

- **화면 목적:** 관리자가 제재 고객 목록과 현재 제재 상태를 확인한다.
- **주요 UI:** 고객 검색, 제재 상태·기간 필터, 제재 목록, 목록 페이지 이동, 상세 보기 버튼.
- **사용자 액션:**
  - 고객을 검색하거나 제재 상태로 필터링한다.
  - 제재 사유, 적용 기간, 현재 상태를 확인한다.
  - 항목을 선택하여 제재 상세 화면으로 이동한다.
- **상태 및 예외:** 조회 결과 없음, 목록 조회 실패, 접근 권한 없음을 구분해 안내한다.

### SCR-014. 제재 상세 화면

- **화면 목적:** 관리자가 제재 근거를 검토하고 제재 유지 또는 해제를 결정한다.
- **주요 UI:** 고객 정보, 제재 상태·사유·기간, 누적 위반 내역, 관련 상담 링크, 폭언 원문 확인 버튼, 제재 해제 버튼, 확인 모달.
- **사용자 액션:**
  - 제재 및 위반 내역을 확인한다.
  - 폭언 원문 확인 버튼을 눌러 원문을 조회한다.
  - 제재를 유지하고 목록으로 돌아간다.
  - 제재 해제를 선택하고 확인 모달에서 확정한다.
- **상태 및 예외:**
  - 원문 조회 요청마다 서버에서 관리자 권한을 확인한다.
  - 원문은 관리자 전용 모달 또는 상세 영역에 표시한다.
  - 해제 성공 후 상태와 목록을 갱신한다.
  - 이미 해제·만료된 제재는 해제 버튼을 비활성화한다.
  - 처리 실패 시 기존 상태를 유지하고 오류를 안내한다.

### SCR-015. 정책 관리 화면

- **화면 목적:** 관리자가 폭언 경고 및 자동 제재 기준을 조회·수정한다.
- **주요 UI:** 현재 정책, 상담 자동 종료 경고 기준, 누적 위반별 이용정지 기간 입력란, 입력 오류 메시지, 저장·취소 버튼.
- **사용자 액션:**
  - 현재 정책을 확인한다.
  - 경고 기준과 제재 기간을 수정한다.
  - 저장하거나 수정 내용을 취소한다.
- **상태 및 예외:**
  - 필수값, 정수 여부, 허용 범위를 검증한다.
  - 유효하지 않은 값은 해당 입력란 아래에 오류를 표시한다.
  - 저장 성공 후 서버의 최신 정책을 다시 조회한다.
  - 저장 실패 시 입력 내용을 유지하고 재시도를 안내한다.
- **확정 필요 사항:** 변경한 정책이 진행 중인 상담과 기존 제재에 적용되는지는 정책 명세서에서 정의한다.

- **주요 UI:** 조회 기간 선택, 전체 상담 건수 카드, 정상·강제 종료 건수, 폭언 발생 건수, 이용정지 고객 수, 통계 차트, 상담 이력 이동 버튼.

  - 통계 카드와 차트를 확인한다.

  - 조회 실패 시 재시도 버튼을 제공한다.
  - 동일한 조회 기간과 집계 기준을 카드·차트에 적용한다.
- **집계 기준:** 폭언 건수는 메시지 기준인지 상담 기준인지, 이용정지 고객 수는 현재 제재 중인지 기간 내 발생인지 API 명세서에 명시한다.

## 5. 작성 시 주의사항

- 사용자 흐름도에 등장한 주요 화면을 화면 목록에 포함한다.
- URL은 실제 프론트엔드 라우팅 기준으로 확정한다.
- 연결 API의 메서드와 경로는 API 명세서와 동일하게 맞춘다.
- WebSocket 접속 경로와 메시지·경고·상태 변경 이벤트는 별도 명세서와 일치시킨다.
- 화면별 상세에는 화면 목적, 주요 UI, 사용자 액션을 작성한다.
- 별도 페이지와 모달·알림·화면 내 상태를 구분한다.
- 정상 상태뿐 아니라 로딩, 데이터 없음, 요청 실패, 접근 거부 상태를 포함한다.
- 권한과 상담·제재 상태는 화면 표시뿐 아니라 서버에서도 검증한다.
- 상담원 화면과 일반 상담 이력에는 폭언 원문을 노출하지 않는다.
- 와이어프레임은 최종 디자인이 아니라 화면 구조를 확인하기 위한 초안으로 작성한다.
- 각 화면의 와이어프레임 이미지 또는 링크는 해당 화면 상세 아래에 첨부한다.
