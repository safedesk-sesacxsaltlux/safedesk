## 1. 회원 정책

| 항목 | 정책 내용 |
| --- | --- |
| 회원가입 | 고객만 스스로 가입할 수 있다. 필수값은 아이디, 비밀번호, 이름이다. 상담원 보호 정책 동의는 필수이며, 화면과 서버에서 확인하고 동의 기록은 저장하지 않는다. (REQ-001) |
| 상담원·관리자 계정 | 회원가입으로 만들 수 없고, 초기 데이터로만 등록한다. |
| 아이디 중복 | 이미 사용 중인 아이디로는 가입할 수 없다. |
| 비밀번호 | 복호화할 수 없는 형태로 암호화하여 저장한다. (NFR-001) |
| 로그인 | 아이디와 비밀번호가 일치하고 회원 상태가 ACTIVE이면 로그인할 수 있다. 로그인 후 역할에 맞는 첫 화면으로 이동한다. (REQ-002) |
| 회원 역할 | 고객은 CUSTOMER, 상담원은 AGENT, 관리자는 ADMIN 역할을 가진다. 한 계정은 역할을 하나만 가진다. |
| 회원 상태 | 회원 상태는 ACTIVE, INACTIVE로 관리한다. INACTIVE 회원은 로그인할 수 없다. |
| 이용정지와 회원 상태 | 이용정지는 회원 상태가 아니라 제재 기록의 해제 일시로 판단한다. 그래야 기간이 지나면 별도 처리 없이 자동으로 풀린다. (REQ-023) |
| 정지 고객 로그인 | 이용정지된 고객도 로그인은 할 수 있다. 정지 사유·해제 일시 확인과 마이페이지 조회만 가능하고 상담은 시작할 수 없다. (REQ-022) |
| 마이페이지 | 로그인한 고객 본인의 상담 이력, 위반 횟수, 제재 상태만 조회할 수 있다. (REQ-031) |

## 2. AI 상담 정책

| 항목 | 정책 내용 |
| --- | --- |
| 상담 시작 | 로그인한 고객 중 이용정지 상태가 아닌 고객만 상담을 시작할 수 있다. (REQ-004, 022) |
| 동시 상담 | 고객 1명은 종료되지 않은 상담을 1개만 가질 수 있다. 상담 신청을 다시 누르면 alert 창이 뜬다. |
| AI 1차 응대 | 상담원 연결 전까지 고객 메시지는 AI가 FAQ를 참고해 답한다. 답변은 생성되는 대로 화면에 이어서 표시한다. (REQ-005) FAQ 데이터베이스에 매칭되는 답변을 불러온다. |
| AI 호출 경로 | 응대·상담 요약의 AI 호출은 모두 AI 게이트웨이 한 곳을 거친다. 게이트웨이는 성공 여부를 정해진 형식으로 돌려주고, 실패 시 대응은 각 기능이 정한다. (NFR-014) |
| AI 응답 제한 시간 | AI 응답을 기다리는 최대 시간은 10초다. **(기본값)** |
| AI 응답 실패 | AI가 오류를 반환하거나 제한 시간을 넘기면 FAQ 키워드 매칭 답변을 대신 제공한다. 맞는 FAQ가 없으면 상담원 연결을 안내한다. 어떤 경우에도 상담은 끊기지 않는다. (REQ-006, NFR-006) |
| AI 목업 | 개발·시연에서는 AI 목업을 쓴다. 목업은 정상·지연·오류 3가지 모드를 가지며, 설정값 하나로 바꾼다. |
| 상담원 연결 요청 | 고객은 AI 응대 중 언제든 상담원 연결을 요청할 수 있다. 요청한 상담은 대기 상태가 되고, 대기 중에는 AI가 답하지 않는다. (REQ-007) |
| 자동 이관 안내 | 맞는 FAQ가 없거나 같은 질문이 2회 반복되면 상담원 연결을 안내한다. 연결 여부는 고객이 정한다. (REQ-008, Could) |
| 폭언 분류 대상 아님 | AI 응대 중 메시지는 폭언 분류·경고·제재 대상이 아니다. 보호 대상은 사람 상담원이기 때문이다. (REQ-014) |

## 3. 상담 연결·실시간 상담 정책

상담 상태는 4가지이며, 표에 없는 방향으로는 바뀔 수 없다. 예를 들어 종료된 상담은 다시 열리지 않는다.

| 상담 상태 | 의미 | 바뀔 수 있는 다음 상태 |
| --- | --- | --- |
| AI_CHAT | AI가 응대 중 | QUEUED(연결 요청), CLOSED(고객 종료) |
| QUEUED | 상담원 연결 대기 중 | IN_PROGRESS(상담원 수락), CLOSED(고객 종료) |
| IN_PROGRESS | 상담원과 상담 중 | CLOSED(고객·상담원 종료, 폭언 자동 종료), TERMINATED(폭언 자동 종료, 상담원 폭언 종료) |
| CLOSED | 종료됨 | 없음 |
| TERMINATED | 폭언으로 강제 종료됨 | 없음 |

| 항목 | 정책 내용 |
| --- | --- |
| 대기열 정렬 | 대기열은 연결 요청 시각이 빠른 순서로 보여준다. (REQ-009) |
| 상담 수락 | QUEUED 상태인 상담만 수락할 수 있다. 두 상담원이 동시에 수락하면 먼저 처리된 1명만 성공하고, 나머지는 "이미 다른 상담원이 수락한 상담입니다"를 받는다. (REQ-010) |
| 상담원 동시 상담 | 상담원 1명은 IN_PROGRESS 상담을 1개만 가질 수 있다. **(기본값)** |
| 메시지 전송 | IN_PROGRESS 상담에서는 해당 고객과 수락한 상담원만 메시지를 보낼 수 있다. CLOSED 상담에는 아무도 보낼 수 없다. (NFR-004) |
| 메시지 저장 | 모든 메시지는 상대에게 전달하기 전에 먼저 저장한다. 실시간 연결이 끊겨도 다시 접속하면 이전 대화를 불러온다. (NFR-008) |
| AI 응대 내역 | 상담원은 수락한 상담의 AI 응대 내역을 볼 수 있다. (REQ-012) |
| 상담 종료 | 고객은 언제든, 상담원은 본인이 수락한 상담만 종료할 수 있다. 종료 시 종료 주체(고객·상담원·시스템)와 사유를 기록한다. (REQ-013) |
| 상담원 회복 시간 | 폭언으로 자동 종료된 상담의 상담원은 종료 후 10분간 새 상담을 수락할 수 없다. **(기본값)** (REQ-033) |

## 4. 폭언 대응 정책

같은 상담에서 폭언 1회는 경고, 2회는 자동 종료다. **(기본값)**

| 항목 | 정책 내용 |
| --- | --- |
| 분류 대상 | IN_PROGRESS 상담의 고객 메시지만 분류한다. 상담원 메시지와 AI 응대 중 메시지는 대상이 아니다. (REQ-014) |
| 분류 결과 | 메시지는 정상 또는 폭언 중 하나로 분류한다. (REQ-014) |
| 1차 판단: 금칙어 | 메시지를 상담원에게 전달하기 전에 금칙어 목록과 대조한다. 금칙어가 있으면 즉시 폭언으로 본다. (NFR-007) |
| 마스킹 | 금칙어로 걸린 메시지는 해당 단어를 `***`로 가린다. (REQ-015) |
| 원문 보관 | 원문은 별도로 저장하며 상담원은 볼 수 없다. 관리자만 조회할 수 있고, 누구도 수정·삭제할 수 없다. (REQ-026, NFR-005) |
| 경고 발송 | 폭언으로 분류되면 고객에게 경고 메시지를 자동으로 보낸다. 경고에는 "한 번 더 폭언 시 상담이 종료되고 이용이 제한될 수 있습니다"를 포함한다. (REQ-016) |
| 자동 종료 | 같은 상담에서 폭언이 2회가 되면 종료 사유를 고객에게 알리고 상담을 TERMINATED로 종료한다. 종료 주체는 시스템으로 기록한다. **(기본값)** (REQ-017) |
| 경고 횟수 범위 | 경고 횟수는 상담 단위로 셈다. 새 상담을 시작하면 0회부터 다시 셈다. 누적은 위반 이력(5장)에서 관리한다. |
| 수동 경고·종료 | 상담원이 직접 보낸 경고도 자동 경고와 같이 1회로 셈다. 상담원이 폭언을 사유로 종료하면 자동 종료와 같이 위반 1회로 기록한다. (REQ-018) |
| 강성 고객 이력 | 상담원은 수락 시 고객의 누적 위반 횟수와 최근 위반 일자만 볼 수 있다. 과거 원문은 볼 수 없다. (REQ-019) |

## 5. 제재(이용정지) 정책

폭언으로 종료된 상담 1건이 위반 1회이며, 누적 위반 횟수에 따라 아래 기간만큼 자동으로 이용정지한다. **(기본값)**

| 누적 상담 종료 횟수 | 이용정지 기간 |
| --- | --- |
| 1회 | 7일 |
| 2회 | 30일 |
| 3회 이상 | 90일 |

| 항목 | 정책 내용 |
| --- | --- |
| 위반 기준 | 폭언으로 자동 종료되거나 상담원이 폭언을 사유로 종료한 상담만 위반으로 본다. 경고만 받고 끝난 상담은 위반이 아니다. (REQ-020) |
| 위반 누적 | 위반 횟수는 고객별로 누적하며 정지가 풀려도 초기화하지 않는다. (REQ-020) |
| 자동 이용정지 | 위반이 기록되는 즉시 누적 횟수에 맞는 기간으로 정지한다. 정지 시작은 상담 종료 시각이고, 해제 일시는 시작 시각에 기간을 더한 값이다. (REQ-021) |
| 정지 중 상담 | 정지된 고객이 상담을 시작하면 정지 사유와 해제 일시를 안내하고 상담을 막는다. 이 판단은 화면이 아니라 서버에서 한다. (REQ-022) |
| 자동 해제 | 해제 일시가 지나면 별도 처리 없이 다시 상담할 수 있다. (REQ-023) |
| 수동 해제 | 관리자는 정지를 즉시 해제할 수 있다. 해제 시 해제 사유를 반드시 입력한다. 해제해도 위반 기록은 남기고, 해제한 관리자와 시각, 해제 사유를 기록한다. (REQ-025) |
| 정책 변경 | 관리자는 경고 발송 기준, 자동 종료 기준 횟수, 위반 횟수별 정지 기간을 바꿀 수 있다. 정책은 저장할 때마다 새 버전으로 기록되며, 바뀐 값은 저장 이후 시작하는 상담과 그 상담에서 생기는 제재에만 적용한다. 이미 진행 중인 상담과 정지는 바꾸지 않는다. 저장 시 변경 일시, 변경한 관리자, 변경 내용을 변경 이력으로 남긴다. (REQ-024) **— should** |
| 정책값 범위 | 경고 발송 기준과 자동 종료 기준은 1\~5회이며, 자동 종료 기준은 경고 발송 기준보다 커야 한다. 정지 기간은 1\~365일 사이 값만 저장할 수 있다. |
| 정책 설정 화면이 없을 때 | REQ-024는 Should다. 구현하지 못하면 위 기본값을 초기 데이터로 넣고 고정한다. |
| 이용정지 부과 | 이용정지는 위반이 기록될 때만 자동으로 생긴다. 관리자나 상담원이 직접 정지를 부과하는 기능은 없다. |

## 6. 이력·조회·통계 정책

| 항목 | 정책 내용 |
| --- | --- |
| 상담 요약 | 상담이 CLOSED 또는 TERMINATED가 되면 AI가 요약해(mockup data) 문의 유형, 처리 내용, 처리 결과로 나눠 저장한다. AI 상담만 하고 끝난 상담도 요약한다. (REQ-029) |
| 요약 실패 | 요약이 실패하면 "요약 없음"으로 저장한다. 상담 종료는 요약 성공 여부와 관계없이 처리한다. (NFR-006) |
| 이력 보관 | 상담 기록과 메시지는 삭제하지 않는다. 종료된 상담의 메시지는 수정할 수 없다. |
| 상담원 이력 조회 | 상담원은 본인이 맡은 상담만 조회한다. 폭언 메시지는 이력에서도 가린 채로 보여준다. (REQ-030) |
| 관리자 이력 조회 | 관리자는 전체 상담을 조회한다. 폭언 원문은 위반 원문 조회에서만 본다. (REQ-030, 026) |
| 고객 이력 조회 | 고객은 본인 상담만 조회한다. 본인 메시지는 본인이 보낸 그대로 보여준다. (REQ-031) |
| 목록 정렬·페이징 | 상담 이력과 제재 고객 목록은 최신순으로 정렬하고 한 페이지에 20건씩 보여준다. (NFR-012) |
| 이력 검색 | 기간, 고객 아이디, 상담원, 종료 사유(일반·폭언 자동 종료)로 검색할 수 있다. |
| 통계 기준 | 통계는 일 단위로 집계한다. 항목은 상담 건수, AI 단독 해결 비율, 폭언 건수, 제재 건수다. (REQ-032) |
| AI 단독 해결 | QUEUED를 거치지 않고 CLOSED가 된 상담을 AI 단독 해결로 본다. 비율은 AI 단독 해결 건수를 전체 종료 상담 건수로 나눈 값이다. |

관리자는 상담에 직접 참여하지 않는다. 상담 수락과 메시지 전송은 상담원 역할만 할 수 있다.

## 8. 예외 처리 정책

| 상황 | 처리 방식 | 응답 예시 |
| --- | --- | --- |
| 로그인하지 않은 사용자 접근 | 인증 실패 처리 | 로그인이 필요합니다. |
| 권한 없는 사용자 접근 | 권한 실패 처리 | 접근 권한이 없습니다. |
| 아이디·비밀번호 불일치 | 인증 실패 처리 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| 중복 아이디 가입 | 요청 실패 처리 | 이미 사용 중인 아이디입니다. |
| 존재하지 않는 회원·상담 | 요청 실패 처리 | 회원을 찾을 수 없습니다. / 상담을 찾을 수 없습니다. |
| 이용정지 고객의 상담 시작 | 요청 실패 처리 + 해제 일시 안내 | 상담 중 폭언으로 이용이 정지되었습니다. 2026-11-18 14:00에 해제됩니다. |
| 진행 중 상담이 있는데 새 상담 시작 | 요청 실패 처리 | 진행 중인 상담이 존재합니다. |
| 이미 수락된 상담 수락 | 요청 실패 처리 | 이미 다른 상담원이 수락한 상담입니다. |
| 진행 중 상담이 있는 상담원의 수락 | 요청 실패 처리 | 진행 중인 상담을 먼저 종료해주세요. |
| 회복 시간 중 수락 | 요청 실패 처리 | 휴식 시간입니다. 잠시 후 수락해주세요. |
| 종료된 상담에 메시지 전송 | 요청 실패 처리 | 종료된 상담입니다. |
| AI 응답 실패·제한 시간 초과 | 실패로 다루지 않고 FAQ 답변으로 대체 | (FAQ 답변) 또는 정확한 답변을 위해 상담원을 연결해 드릴까요? |
| 폭언 감지(1회) | 메시지 가림 + 고객에게 경고 | 폭언이 감지되었습니다. 한 번 더 폭언 시 상담이 종료되고 이용이 제한될 수 있습니다. |
| 폭언 감지(2회) | 상담 자동 종료 + 이용정지 | 반복된 폭언으로 상담이 종료되었습니다. 7일간 상담을 이용할 수 없습니다. |
| 정책값 범위 초과 | 요청 실패 처리 | 경고 발송 기준과 자동 종료 기준은 1\~5회, 정지 기간은 1\~365일로 입력해주세요. 자동 종료 기준은 경고 발송 기준보다 커야 합니다. |
| 입력 값 검증 실패 | 요청 실패 처리 | 입력 값을 확인해주세요. |

## 작성 시 주의사항

- 정책은 “가능하다 / 불가능하다”가 명확하게 보이도록 작성한다.
- 화면에서 버튼을 숨기는 것만으로는 막을 수 없다. 이용정지, 동시 수락, 상담 접근 제한은 반드시 서버에서 검사한다.
- 팀원마다 다르게 이해할 수 있는 부분은 반드시 정책으로 정리한다. 예: 경고 횟수는 상담 단위, 위반 횟수는 고객 단위로 셈다.
- 정책이 바뀌면 요구사항 정의서, API 명세서, 화면 설계서, ERD도 함께 수정한다.
