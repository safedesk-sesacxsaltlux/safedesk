## 1. 기능 요구사항

시연의 핵심 흐름(AI 응대 → 상담원 연결 → 폭언 마스킹 → 경고 → 자동 종료 → 이용정지)에 필요한 기능을 Must로 두었다. 사용자 역할은 고객·상담원·관리자 3가지다.

| 요구사항 ID | 분류 | 요구사항명 | 요구사항 내용 | 우선순위 | 담당자 |
| --- | --- | --- | --- | --- | --- |
| REQ-001 | 회원 | 회원가입 | 고객은 아이디, 비밀번호, 이름을 입력하고 상담원 보호 정책에 동의해야 가입할 수 있다. 아이디는 중복될 수 없고, 비밀번호는 단방향 암호화해 저장한다. 정책 동의 여부는 화면과 서버에서 확인하며 DB에는 저장하지 않는다. | Must | 장건웅 |
| REQ-002 | 회원 | 로그인 | 사용자는 아이디와 비밀번호로 로그인하고, 역할에 맞는 첫 화면(채팅창·상담원 콘솔·관리자 화면)으로 이동한다. | Must | 장건웅 |
| REQ-003 | 회원 | 로그아웃 | 사용자는 로그인 상태에서 로그아웃할 수 있다. | Must | 장건웅 |

| REQ-005 | AI 상담 | AI 1차 응대 | 고객 메시지에 **Mock AI가 FAQ 데이터에서 답변을 찾아** 답하며, 답변은 **순차 출력 방식으로** 화면에 표시된다. | Must | 심소민 |
| REQ-006 | AI 상담 | AI 응답 실패 시 상담 유지 | AI가 오류를 반환하거나 10초 안에 응답하지 않아도 상담은 끊기지 않아야 한다. 이때 시스템은 FAQ 키워드 매칭 답변을 대신 제공하고, 맞는 FAQ가 없으면 상담원 연결을 안내한다. 이 동작은 AI 목업의 지연·오류 모드로 검증한다. | Must | 심소민 |
| REQ-007 | AI 상담 | 상담원 연결 요청 | 고객은 AI 상담 중 상담원 연결을 요청할 수 있고, 요청한 상담은 대기열에 들어간다. | Must | 심소민 |
| REQ-008 | AI 상담 | 자동 이관 안내 | AI가 FAQ에서 답을 찾지 못하거나 같은 질문이 2회 반복되면 고객에게 상담원 연결을 안내한다. | Could | 심소민 |
| REQ-009 | 실시간 상담 | 상담 대기열 조회 | 상담원은 연결을 기다리는 상담 목록을 대기 시간 순으로 조회할 수 있다. | Must | 정혜영 |
| REQ-010 | 실시간 상담 | 상담 수락 | 상담원은 대기 중인 상담을 수락할 수 있다. 이미 수락된 상담은 다른 상담원이 수락할 수 없다. | Must | 정혜영 |
| REQ-011 | 실시간 상담 | 실시간 채팅 | 상담원과 고객은 새로고침 없이 메시지를 주고받을 수 있다. | Must | 정혜영 |
| REQ-012 | 실시간 상담 | AI 응대 내역 확인 | 상담원은 수락한 상담의 AI 응대 내역을 볼 수 있다. | Should | 정혜영 |
| REQ-013 | 실시간 상담 | 상담 종료 | 상담원 또는 고객은 상담을 종료할 수 있다. | Must | 정혜영 |
| REQ-014 | 폭언 대응 | 폭언 감지·등급 분류 | 시스템은 상담원 연결 후 고객 메시지를 금칙어 규칙으로 정상/폭언 으로 분류한다. | Must | 한수민 |

| REQ-016 | 폭언 대응 | 경고 자동 발송 | 폭언 메시지가 감지되면 고객에게 경고 메시지를 자동으로 보낸다. | Must | 한수민 |
| REQ-017 | 폭언 대응 | 상담 자동 종료 | 한 상담에서 폭언이 정책에 정한 횟수만큼 감지되면 상담을 자동 종료하고 종료 사유를 고객에게 알린다. | Must | 한수민 |
| REQ-018 | 폭언 대응 | 수동 경고·종료 | 상담원은 자동 판단과 별개로 직접 경고를 보내거나 상담을 종료할 수 있다. | Should | 한수민 |

## 2. 비기능 요구사항

AI 응답은 목업이지만, 나중에 실제 AI로 바꿔도 상담이 멈추지 않도록 목업의 지연·오류 모드로 장애 상황을 재현해 검증한다.

| 요구사항 ID | 분류 | 요구사항명 | 요구사항 내용 | 우선순위 | 담당자 |
| --- | --- | --- | --- | --- | --- |
| NFR-001 | 보안 | 비밀번호 암호화 | 사용자의 비밀번호는 복호화할 수 없는 형태로 암호화하여 저장한다. | Must | 장건웅 |
| NFR-002 | 보안 | 인증 처리 | 로그인한 사용자만 상담 기능을 쓸 수 있으며, 실시간 채팅 연결에도 같은 인증을 적용한다. | Must | 장건웅 |
| NFR-003 | 보안 | 역할별 권한 | 고객·상담원·관리자는 자기 역할에 허용된 화면과 API만 쓸 수 있다. | Must | 장건웅 |
| NFR-004 | 보안 | 상담 접근 제한 | 고객은 본인 상담만, 상담원은 본인이 수락한 상담에만 메시지를 보내고 볼 수 있다. | Must | 정혜영 |
| NFR-005 | 보안 | 위반 원문 보호 | 폭언 원문은 관리자만 조회할 수 있고, 법적 대응 증빙을 위해 수정·삭제할 수 없다. | Must | 한수민 |
| NFR-006 | 가용성 | AI 장애 격리 | **Mock AI가 지연·오류 모드일 때도** 채팅과 상담원 연결은 계속 동작한다. | Must | 심소민 |
| NFR-007 | 성능 | 메시지 전달 지연 | 상담 메시지는 **금칙어 판정·마스킹을 거쳐** 1초 안에 상대에게 전달된다. | Must | 한수민 |
| NFR-008 | 가용성 | 연결 끊김 대응 | 실시간 연결이 끊겨도 메시지는 유실되지 않고, 다시 접속하면 이전 대화를 이어서 볼 수 있다. | Must | 정혜영 |
| NFR-009 | 데이터 | 데이터 무결성 | 존재하지 않거나 종료된 상담에 대한 메시지·수락·제재는 저장되지 않아야 한다. | Must | 유능한 |
| NFR-010 | 데이터 | AI 호출 기록 | 삭제 (또는 우선순위를 Won’t로 바꾸고 “실제 AI 연동 시 추가”라고 비고 작성) | Won’t | 심소민 |
| NFR-011 | 사용성 | 오류 메시지 | 입력 오류, 권한 오류, 이용정지 상태에서는 사용자가 이해할 수 있는 메시지를 제공한다. | Must | 전원 |
| NFR-012 | 성능 | 목록 페이징 | 상담 이력과 제재 고객 목록은 페이징하여 한 번에 너무 많은 데이터를 조회하지 않는다. | Should | 장건웅, 유능한 |
| NFR-013 | 유지보수 | API 응답 형식 | 성공 응답과 실패 응답의 구조를 가능한 한 일관되게 유지한다. | Must | 유능한 |
| NFR-014 | 유지보수 | AI 연동 단일화 | **AI 응대·요약** 호출은 AI 게이트웨이 한 곳을 거친다. 목업을 실제 AI로 바꿀 때 다른 기능 코드는 고치지 않는다. | Should | 심소민 |

## 3. 우선순위 기준

| 우선순위 | 의미 | 개수 (기능 / 비기능) |
| --- | --- | --- |
| Must | 프로젝트 핵심 기능으로 반드시 구현해야 한다. | 22 / 11 |
| Should | 주요 기능이지만 일정에 따라 조정할 수 있다. | 8 / 3 |
| Could | 시간이 남으면 구현할 수 있는 부가 기능이다. | 2 / 0 |
| Won't | 이번 프로젝트 범위에서는 구현하지 않는다. | 아래 4개 |

**Won't (이번 범위 제외, 발표의 확장 방향으로만 소개)**

- 실제 LLM API 연동 (AI Agent 기능 기획서는 2차 디벨롭 범위)
- 음성 상담(전화 연결, 음성 변환)
- 주문·배송 등 실제 업무 시스템 연동과 AI의 도구 호출(Agent)
- 여러 서버로 확장하는 구성
- 3회 이상 위반 시 고소·고발 등 법적 조치 연계

## 4. 작성 시 주의사항

- 요구사항은 “무엇을 할 수 있어야 하는가” 중심으로 작성한다. 구현 방법(WebSocket인지 폴링인지 등)은 설계 문서에 적는다.
- 요구사항 ID는 API 명세서, 화면 설계서, 테스트 시나리오와 연결할 수 있도록 유지한다.
- Must 기능부터 구현하고, 프로젝트 중 요구사항이 바뀌면 이 문서에 바로 반영한다.
